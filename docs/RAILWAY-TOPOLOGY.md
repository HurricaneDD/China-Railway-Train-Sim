# 派生铁路连接、断点与路径预览

分省加载、原始 part 与 V1 区段 ID 不变。节点是 2 m 内端点及既有内部顶点的几何候选，不是 OSM 共享 node；数据仅含 way 级 `osm_id`，不能证明股道或联锁。二维边中途交叉没有共享顶点时不连接。

## 桥隧与层级

- 程序只依据原始属性识别桥隧：`bridge === 'T'` 为桥，`tunnel === 'T'` 为隧；`'F'`、缺失或其他值均不算。`layer` 是独立属性。
- 桥隧不是结构识别，不使用 DEM、坡度或几何形态；主应用也不会因为桥隧标签改变轨道高程或生成隧道模型。
- 2026-11-02 修正后的核心规则：**原始坐标完全重合的共享端点**（间隙 `< 0.01 m`）是 OSM 节点共享的证据，桥/隧/`layer` 标签差异不再作为切断正线的独立判据。若转角不超过 35°，属性变化仍保留为可行驶候选，并标为 `uncertain`；只有几何切线不足、接近掉头（≥150°）、间隙超过 0.25 m 或内部顶点未重合时才隔离。
- 原属性相同的共享端点仍按“原始坐标重合、方向连续性推定”处理；桥隧直连、桥与桥不同 `layer`、地面与桥隧交界都可以通过，但会显示推定提醒。
- 非完全重合的 0.01–0.25 m 连接仍保守：要求桥隧状态确实变化、层差不超过 1、转角不超过 35°、且不是桥隧直连；仅层差或仅属性冲突的非共享端点不自动连接。
- 端点接入另一折线内部既有顶点时，间隙超过 0.01 m 会被隔离。二维交叉没有共享顶点、省界未加载邻省、原始 OSM 缺口或真实尽端仍可能表现为断点，不能用前进操作折返。

### 江苏实测（2026-11-02，派生几何诊断）

同一份江苏原始数据，修正前后：

| 指标 | 修正前 | 修正后 |
|---|---:|---:|
| 有向无有效出边边界 | 2,616 | 1,735 |
| 其中存在被过滤候选 | 894 | 13 |
| 桥隧/层级属性冲突被拒候选 | 1,108 | 0 |
| 弱区段连通分量 | 469 | 100 |
| 最大弱分量区段数 | 3,535 | 9,470 |

修正前 1,108 个被拒属性候选全部位于原始坐标完全重合的共享端点；其中 812 个只是 `layer` 不同，其余是桥/隧标签过渡（含少量桥隧直连和层差 2–3）。南京周边京沪高铁、沪宁城际、宁杭高速、宁芜、仙宁等正线因此出现多处无法继续驾驶的断点。修正后仍保留 1,722 个几何度数为 1 的端点；它们多数是站场尽端、支线终点或 OSM 原始缺口，不等同于正线错误，也需要人工核查。以上计数是算法输出，不是真实铁路可达性、道岔数量或工程结论；诊断脚本只分析所选省份。

离线统计仍可运行：

```bash
npx vite-node scripts/railway-diagnostics.ts 320000
```

## 断点人工检查

`dev/raliway-check/` 提供分省只读检查页（开发地址 `/dev/raliway-check/`，构建输出 `dist/dev/raliway-check/`）：

- 按省加载当前正式 GeoJSON，显示普通/桥/隧区段；
- 以红色标出“存在被过滤连接”的断点，橙色标出“邻近线路未接入”，灰色标出孤立端点；
- 点击断点查看来路区段、被拒候选的角度/间隙/属性、最近线路和 OSM ID；
- 可加载相邻省份复核省界，可导出本省断点 JSON。

该页与驾驶共用 `RailNetwork.connectionsAt/nextBoundary`，不修改正式数据。检查页的断点分组、最近线路和弱分量统计仍是几何启发式；修复原始数据后必须重新加载并重新驾驶验证。详细说明见 `dev/raliway-check/README.md`。

## 路径预览

多个有效出边保留为不同物理选项；没有按相近角度合并。每个选项只沿唯一有效出边追踪，最多 2 km 或 80 个边界，遇下一分岔、终点或重复访问即停，不推断可达车站。原始线路名保持原样；无名出边仅在前方唯一走廊出现唯一名称时显示标注“推断”的连接区段，多个名称或无名称则显示未识别轨道。这是路径辅助描述，不是确认的线路归属。

弹窗预览以列车进入方向向上、东西和南北使用相同尺度绘制，选中路径置顶高亮；独立的编号索引按列表顺序排列，并注明不代表股道位置，点击后另行确认。接近唯一的、带疑点的可通行桥隧过渡时 HUD 显示推定提醒。开发环境展开诊断可复制候选、方向、角度、间隙、属性、过滤理由及预览停止原因。该示意并非地图、精确站场图或卫星影像。没有共享节点 ID、轨道高程、铁路关系数据和现场核验，不能保证全国连续可行或真实线路名称；开发者应以人工核查和真实驾驶补充证据。

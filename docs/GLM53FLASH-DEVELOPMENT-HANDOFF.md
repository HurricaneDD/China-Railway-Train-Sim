## 目标

在现有 Vue + TypeScript + CesiumJS 纯静态应用上，完成能推广到全国数据的：

1. 默认机车、客车和驾驶室的统一建模，合理贴轨、转向架姿态和轮轴动画。
2. 独立于地表的铁路纵断面，给轨道、车辆、驾驶室、坡度和动力学提供一致的高程与导数。
3. 普通路基、路堤、路堑、桥梁和隧道的不同地形/结构处理。
4. 可持续加载和释放的近景铁路走廊、基础材质及沿线环境。
5. 清晰的来源、推定程度、诊断工具和验收证据。

保留全国自由驾驶、车站始发选线、道岔选择、倒车历史和原有存档。先让 3–5 km 样板达到质量要求，再扩展通用规则与全国抽查，不能把“全量”实现为只对南京南硬编码。

## 不能直接照搬的实验结论

- 人工 22 m 鼓包验证了平滑与局部替换的有效性；真实走廊最大修正 45.11 m 位于 OSM 隧道段，这并不证明山体高程错误。
- 实验 10 m 地表采样最大坡度 513.26‰；按现有原始顶点插值和 GameSession 采样公式复现的最大输入坡度约 84.85‰。不要把二者写成同一个指标。
- 实验 fitter 的 35‰ 是一个演示参数，绝不是全国线路统一标准。它只保证相邻高程差，不保证竖曲线平顺，实测相邻坡度变化仍达 69.75‰/10 m。
- 在隧道上方做连续二维裁剪会把山体切成露天槽。这是失败示范，不能作为隧道成品。
- `globe.getHeight` 在裁剪后仍可返回原地形（约 80.18 m），并不会返回实验轨面（约 35.09 m）。视觉替换和物理高程必须分别接线。
- 原型按整条 5 km 测试路径拟合，一次创建完整近景。不是已验证的全国增量算法，也不是生产缓存/资源管理实现。
- 实验车辆只用盒体和圆柱说明基本结构，驾驶员眼点检查隐藏外部模型。它不是正式车型或完整驾驶室的交付模板。

## 第一阶段：建立统一的铁路纵断面

推荐单独模块 `src/core/railProfile.ts`（名称可调整），不要把逻辑散落在相机、钢轨和动力学里。

建议对外提供的语义：

```ts
type HeightConfidence = 'surveyed' | 'manual' | 'inferred' | 'unknown';
interface RailProfileSample {
  height: number;
  gradeForward: number;
  confidence: HeightConfidence;
  revision: string;
}
// 无有效数据时返回 undefined 或明确的状态，不能把失败转换成实测零值。
sampleRailProfile(segmentId: string, originalOffset: number): RailProfileSample | undefined;
```

实施要求：

- 高程优先级：有来源的人工/实测覆盖 > 结构控制点推定 > 可配置的鲁棒地形推定 > 明确未知。
- 保留原始 WGS84 平面线、派生区段 ID、原区段里程、原始属性；不在 GeoJSON 中补假数据，不移动点来掩盖高程问题。
- 采样按米制距离组织；中值/异常值检测只是预处理，还应约束坡度变化，生成可查询的一阶连续纵断面。
- 平滑窗口必须跨越短 OSM 区段。共享物理连接的高程应一致；二维临近、跨线桥和不同层轨道不能因距离近而共用高度。
- 桥隧属性是分类线索，不是桥面标高、埋深或绝对高程。不要用 `layer * 常数` 生成真实轨面。
- 路径含分岔时，不能私自选择玩家尚未选择的出口；保证已有来路/主区段的高程稳定，未定后续路径采用可解释边界处理。
- 在线 DEM 的均方误差、空间分辨率、轨道高度来源与人工覆盖须可追踪。高度基准区分椭球高与正高，不混用。
- 先确定可信锚点，检查约束是否可行。锚点不可行时报告冲突，不悄悄改锚点或输出非有限数。
- 需要处理采样缺口、端点、反向访问、跨省别名、读档、provider 切换和修订版本。
- 让轨道远近层、车体、编组历史、驾驶室和动力学都读取该模块。不得只把 HUD 坡度 clamp 到小值而让钢轨继续爬鼓包。
- 动力学中的坡度始终对应车体前向轴；倒车只影响行驶方向显示，不重复翻转重力。
- 不改牵引力来掩盖高程错误。现有陡坡辅助可保留兼容，但要清楚区分触发原因。

性能：实验 fitter 是二次复杂度，只供小样本对照。生产实现用有界窗口、空间索引、滑动统计和必要的 Worker，避免 50× 时同步拟合整省。缓存由数据/覆盖/profile 版本控制；250 m 块只是渲染分块，不应各自拥有互不一致的纵断面。

## 第二阶段：局部地形与铁路结构

推荐 `TerrainCorridorManager` 与现有 `SceneryManager` 协调，按可见范围管理。

| 场景 | 应实现的行为 |
|---|---|
| 普通地面段 | 按轨面/路基高程生成合理横断面，平滑接回原地表 |
| 路堤 | 道床下方填方、边坡与必要护坡，不能留下悬空钢轨 |
| 路堑 | 局部开挖、边坡或挡墙，不切掉走廊以外真实山体 |
| 桥梁 | 独立桥面/桥墩/栏杆；桥下原始地表与水系保留 |
| 隧道 | 洞体、洞口、内壁、出口过渡；上方山体保留 |
| 站场/平行线 | 以共同场地或兼容横断面处理，避免多条走廊相互切坏 |

技术要求：

- Cesium 1.127 已有 `Globe.clippingPolygons`，用 `isSupported` 检查 WebGL 2。先在本版本实现，升级引擎须另有必要性和回归证据。
- 裁剪是隐藏，不是更改 DEM；替代地面必须自己补。源地形查询和碰撞/物理查询不能混淆。
- 新网格就绪后才原子切换裁剪与场景；卸载时先恢复原地形，再移除替代网格，避免黑洞。
- 实验在裁剪边界出现过黑色细缝，2 m 覆盖余量改善了本场景，但没有证明全国无缝。生产处理跨块接缝、盖边/skirt、端盖、LOD 切换与相邻走廊合并。
- 不要用一个沿整条隧道投影的 Globe 二维裁剪多边形代替地下洞体。二维裁剪贯穿地表，无法表达保留山顶的三维洞穴；只在必要的洞口局部处理地表，内部靠自建洞体和正确视点/遮挡。
- 隧道覆土、桥梁净空和路基填挖无法可靠推定时，应允许独立场景覆盖和低可信状态，不生成看似真实的固定值。
- 缓存 key 应覆盖几何/高程/材质/覆盖版本。request generation、任务取消、资源销毁、旧结果隔离必须沿用现有经验。
- 远景沿用 Cesium 世界地形；近景只处理需要的范围。裁剪多边形数量和更新频率设预算，不把全国所有铁路同时裁剪。
- 如后续使用离线修正 DEM，输出静态 GeoTIFF/terrain 数据与处理记录；明确数据许可、垂直基准、空间范围和源数据差异。

## 第三阶段：默认车辆与驾驶室

以自制的通用国产电力机车 + 现有绿皮客车编组为起点，或选择有资料/合法资源的具体车型。几何、物理规格和资料来源分别明确。

- 同一套车体尺寸、车轮接触基准、模型原点和局部轴约定：当前长轴为本地 X，WGS84/ECEF/ENU 转换不要靠试转 90° 掩盖错误。
- 模型包含车头轮廓、前窗、侧窗/门、车顶设备、转向架、轮轴、车钩和贯通关系。纯色大盒体不能作为最终默认效果。
- 推荐 glTF/GLB 标准资源 + 共享材质；也可程序化生成，但必须具备可检查的近景轮廓与材质细节。
- 前后转向架取同一“已选路线走廊”上的位置，车体据此求姿态。不能把车厢/轮轴吸到空间上更近的另一条平行线。
- 独立转向架偏航、轮轴滚动、车体俯仰；倒车时轮转反向但车头朝向不瞬间反转。跨区段、急曲线、存读档和缺尾路径需验证。
- 车体视觉俯仰可用轴距滤波，但物理轨面不能靠每帧 lerp 随机漂移；相机滤波与轨面真实性分开。
- 不逐帧创建 Entity、Geometry 或 Material。可动部件使用节点变换，共享几何/材质，按距离切换细节。
- 现有 CabRenderer 仪表与控制可继续使用，统一眼点、玻璃与车体基准；内外视角切换处理重复车壳、透明排序和近裁剪。
- 实验仅验证了简单结构可以工作，没有验证轮轨接触精度、悬挂或正式车型比例，这些属于你的验收责任。

## 第四阶段：材质、重复设施与沿线环境

- 钢轨顶面/侧面、道砟、混凝土枕、边坡使用合理的世界尺度 UV 和粗糙度，不把大块卫星照片放大当作道砟。
- 近景保留钢轨/轨枕实体，远景降细节；避免每根枕木/护栏生成一个 Entity。沿用现有 Primitive 合批与 250 m 场景块。
- 接触网按可配置线路/场景清单启用，不从一个线名推断全国电气化。不能把程序化设施编号当真实公里标或信号。
- 建筑先按真实轮廓/有来源高度做简模，近处立面细节、远处简化；不必先引入全国照片建模或完整 OSM2World 重型流程。
- 站台、站棚、站房先做有资料的样板，再支持独立覆盖；单个车站坐标不足以生成真实站场。
- 资产记录来源、作者、许可证、修改情况。参考项目 Three.js 代码不能直接搬进 Cesium 场景，也不要复制日本轨距、车型和桥隧参数。

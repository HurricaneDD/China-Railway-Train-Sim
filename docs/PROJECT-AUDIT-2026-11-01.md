# 项目运行与实施审查（2026-11-01）

> 后续启动修复状态：用户要求缩小范围后，已固定兼容的 Cesium 子依赖并将地图引用改为 shallowRef；dev、build、7 项测试通过，可见浏览器已进入广州南驾驶并确认基础输入和时间推进。以下为修复前审查记录，依赖与代理问题已实施修复，其余项仍待处理，长时间稳定性尚未验收。当前以 AGENTS.md 最新更新日志为准。

## 结论与范围

当前实现具备前端架构、数据接入和驾驶原型，但不能据此认定为稳定可驾驶的 V1。问题分成依赖环境、开发构建链、Vue/Cesium 对象生命周期、铁路拓扑和车辆运动几个独立层面。

本次使用 macOS arm64、Node 24.19.0 / npm 11.17.0，先读取 AGENTS.md 和 data/README.md，再检查源码、执行构建/测试、启动开发服务器、托管 dist 并检查可见浏览器日志，以及通过临时脚本调用核心逻辑。临时核心诊断使用真实广东数据，禁用 RAF 与远程地形，不代替完整 UI 验收。未修改应用源码、正式数据、package.json 或锁文件；执行了 npm ci，重建了 dist。

## 一、为什么跑不起来

### 1. 当前依赖目录来自 Windows，不能直接用于 Mac（已复现）

- 初始 node_modules/.bin/vite、vitest、vue-tsc 是无执行权限的普通文件。
- 初始原生模块只有 @esbuild/win32-x64 与 Rollup Windows 包。
- npm run build / npm test 初始报 Permission denied；直接使用 Node 启动 Vite 报缺少 @rollup/rollup-darwin-arm64。
- 保留 package-lock.json，执行 npm ci --no-audit --no-fund 后，build 和 7 项测试全部通过。
- 结论：不要分发或跨系统搬运 node_modules；这是本机第一层阻断，但不是全部原因。

### 2. npm ci 后开发服务器仍启动失败（已复现）

npm run dev -- --host 127.0.0.1 短暂显示 ready 后因依赖预构建失败退出：

`Missing "./lib/zip-no-worker.js" specifier in "@zip.js/zip.js" package`

锁文件实际组合为 Cesium 1.127.0、engine 15.0.0、widgets 11.1.0（又引入 engine 16.0.0）、zip.js 2.24.0。源码仍引用 ZIP 包已不导出的子路径。生产构建插件使用预构建 Cesium.js 并将 cesium external，而 dev 走源码依赖预构建，所以生产 build 成功不能证明 dev 可用。

建议先验证并固定兼容的 Cesium/engine/widgets/zip.js 组合，或整体迁移到经实际验证的版本；不要通过任意修改 node_modules 或删除锁文件掩盖问题。上游同类报告：https://github.com/CesiumGS/cesium/issues/12883 。

### 3. 页面能打开，但地形渲染仍会停止（实际日志 + 最小对照复现）

可见浏览器日志记录到 terrain tile 加载异常及 Rendering has stopped，堆栈在 TileAvailability 的 rectangles 读取，不是上一轮修复的相机坐标写入异常。

App.vue:22 使用 ref<CesiumMap>()，接收实例后深度代理其 viewer、地形 provider、elevation 等内部对象；Cesium 内部仍持有原始引用，调用 map.renderRailway 等方法时则可能经代理访问同一状态。TileAvailability 四叉树依赖父子对象引用一致性。

独立对照：创建 TileAvailability、加入根瓦片与逐层单瓦片范围，然后按经纬网查询。全部操作使用原始对象时 0 次异常；通过 Vue reactive 包装对象写入、原始对象查询时出现 423 次 reading 'rectangles' 异常。该实验不请求网络、不使用项目 Token。

建议 map 使用 shallowRef 或 markRaw；保持 Cesium 实例、provider 与服务对象为非深度响应式，只向 Vue 暴露 HUD 快照。同时加入 scene.renderError 监测、用户可见错误和重新初始化路径。上游同类堆栈：https://github.com/CesiumGS/cesium/issues/11769 。尚未在本项目修改后完成 A/B 长时间回归，因此不宣称此处是所有地形故障的唯一原因。

### 4. 地图服务是启动硬依赖（静态审查）

CesiumMap.initialize 串行等待远程地形与影像，成功后才 ready；App 新游戏依赖 mapReady。远程权限、网络或服务失败会阻止整个驾驶入口。当前无超时、重试、椭球地形/基础底图降级，错误提示消失后界面仍可能停留“正在加载”。本次没有证据表明 Token 已失效。

## 二、现有驾驶实现缺陷

### P1：拓扑将正常桥隧过渡切断

railway.ts:131 要求端点 layer、bridge、tunnel 全相同。这避免部分立交误连，却也拒绝同一线路从地面进入桥梁或隧道的正常属性变化。

按当前算法仅载入广东得到 13,260 区段、24,808 节点，其中 23,434 个节点仅关联一个区段；有 7,983 组坐标精确重合到小数点后七位、但桥隧/层级属性不同的孤立端点组。这些是需要核验的断连候选，不能把全部数量直接当成真实铁路应连接数量。现有严格规则确实使图高度碎片化；advance 遇到无后续区段只将速度归零，没有明确断路提示。

建议保留原数据，在独立派生图中使用共享端点、方向连续性及可取得的 OSM 节点身份判断连接；桥隧标签作为区段属性，属性变化进入审查规则，二维交叉仍不自动连接。先输出连通分量、断点位置和车站可达里程报告，再选取一条线路人工验收。

### P1：路线历史不能持续增长，车厢无法保持跟随间距

session.ts:310 将移动不足 1.5 米的新点直接替换最后一点。正常 60 Hz 驾驶每步往往小于 1.5 米，比较基准不断前移，结果长期不追加固定历史点。historyPoint 又只返回前一条记录而不插值。

真实广州南起点，以 10 m/s、1/60 秒步进移动 100 米：历史长度仍为 112；机车位移约 100 米，第一节车厢位移约 20 米，两者中心距离约 105 米，远超配置的约 24 米。

建议分离“已提交的固定间隔历史”和“当前机车点”，按累计路线距离插值；路径应保存区段及进出方向。回退时使用已有路径和车辆顺序，不能只以绝对累计距离重新解释历史。

### P1：倒车跨区段方向错误

session.ts:233 进入新区段时只根据 entersAtStart 设置 direction，未包含当前 signedDistance 的符号。倒车从某区段起点跨入相邻区段末端后，应保持负速度从末端继续向内移动；现实现会再次尝试从该末端退出，可能往返跨节点并触发 8 次循环保护。

两段直线的最小场景中，从 b 区段 offset=1 倒退 2 米，预期 a.offset=99，实际停留 b.offset=0，累计只移动 1 米。

### P1：分岔按钮传递未绑定的实例方法

App.vue:344 使用 @choose="session.chooseJunction"；chooseJunction 是依赖 this 的普通类方法，作为事件回调传出存在 this 丢失。建议显式包装为 (id) => session.chooseJunction(id) 或将方法绑定实例，并实际点击分岔按钮回归。本项为代码路径审查，未完成 UI 点击复现。

### P1：坡度坐标与有符号动力学不统一

refreshSlope 根据速度/换向翻转 ahead/behind，stepDynamics 却在固定有符号速度轴上直接减去 gradeForce。倒车时重力不应仅因运动方向变化而改变物理方向。区段端点处采样被截断，但分母仍取 span*2，也会低估坡度。建议以车辆前向为物理轴，单独转换 HUD 的“沿运动方向上坡/下坡”显示，采样距离使用真实路线长度并跨区段取点。

### P2：可见轨道与列车高度不可靠

- RailRenderer 只采样前 6,000 个顶点，后续未缓存点默认高度 0；山区可能埋轨或高度突变。
- session 只补采样最后 30 条历史，初始较长编组历史可能长期保持 0 高度。
- render 开始即 clear，然后等待最多 60 批地形请求；会出现旧轨道先消失、新轨道迟迟不出现。
- 异步渲染无请求代次/取消；过期请求可能覆盖或叠加后续画面。
- segmentsNear 以顶点是否进入半径判断，长线段穿过视野但两端在外会被漏掉；空间索引也只记顶点所在网格，遗漏跨过的网格。数量截断未按与玩家的距离或当前行车路径排序。

建议优先保证玩家当前及前方轨道，按距离/路线裁剪、固定间隔采样、缓存/队列去重，完成新 Primitive 后再原子替换旧轨道。

### P2：存档和交互仍有一致性风险

- IndexedDB 在 request.onsuccess 就报告成功，没有等待 transaction.oncomplete 或处理事务最终 abort，可能过早提示保存成功。
- 导入仅检查部分范围和结构；经纬度范围、历史单调性、编组内容等不足。导入同 ID 直接 put 会覆盖已有存档。
- 派生 ID 使用省份 + Feature 数组下标；跨省去重取决于加载先后，恢复只先加载 position.province，长期稳定性不足。需要数据版本和稳定区段身份。
- 打开设置不暂停运行；失焦/切后台不统一清除按键状态，可能残留牵引输入。
- 地图选点界面的全屏 workspace-backdrop 接收点击，挡住 Cesium canvas；小屏下 new-game-panel 更占满屏幕。需要实际验证并修复地图拾取的事件层级。

## 三、实施过程的问题

1. **验收层次混淆。** 数据字段正确不证明路网可行驶；构建通过不证明开发服务器能启动；进入 HUD 不证明车辆运动、编组、分岔或存档正确。
2. **测试覆盖偏离核心风险。** 现有 7 项测试只覆盖基础几何、简单动力学和错误存档对象，没有 session / railway 测试，也没有分岔选择、倒车跨节点、编组距离、恢复轨迹与地图生命周期测试。
3. **仿真状态与表现对象的边界不完整。** dynamics 与 Cesium 解耦是优点，但 session 仍直接依赖地形服务、存储和 RAF。建议注入时钟、海拔查询与存档接口，便于确定性回放和离线测试。
4. **“安全约束”没有做反例验证。** 全属性相同才能连接避免误连，但正常桥头也被切断；历史压缩减少点数，却删除了车厢所需路径。每项约束都应同时验证要防止的错误与应允许的正常情况。
5. **功能范围超前于可靠性。** 全国覆盖、车站搜索、地形、存档和 UI 都已铺开，但一条线路的持续驾驶仍不可靠。继续堆模型或信号会增加定位成本。
6. **本地目录不是 Git 仓库。** 当前 git status 报 not a git repository；虽有 workflow 文件，但此目录没有可直接检查的提交/回滚/远端配置。不能据此认定 GitHub Pages 已接通。

## 四、建议实施顺序与验收标准

| 阶段 | 工作 | 通过条件 |
| --- | --- | --- |
| P0：可启动、可诊断 | 兼容依赖组合；Cesium 非响应式实例；加载超时、失败重试和降级；渲染异常监控 | 干净安装后 dev、build、preview 均可运行；根路径/仓库子路径资源可读；可见浏览器驾驶和缩放至少 10 分钟无渲染中止；断网有明确状态 |
| P1：可靠线路与运动 | 派生拓扑审查；跨节点前进/后退；固定间隔历史与插值；坡度符号；分岔绑定 | 一条人工核验路线连续运行至少 20 km，含桥隧过渡、多个区段、分岔和倒车；无无故停车；车辆路径间距保持配置值；断头有明确原因 |
| P2：完整使用闭环 | 存档事务完成与版本；导入冲突；地图点选；暂停和失焦；异步轨道替换 | 新游戏→驾驶→保存→刷新恢复→导出→导入全流程通过；恢复前后位置/车速/编组一致；鼠标与触摸点选均可用 |
| P3：规模与表现 | 派生图离线预处理、Worker、空间索引、地形队列与内存预算；再增加模型和运营系统 | 用统一场景记录帧耗时、最长主线程任务、内存和请求数，再决定优化；扩展前已有回归基线 |

不需要为了这些问题立刻迁移框架或增加后端。Vue + Cesium + 静态部署可继续保留，先建立可信的派生路网和可回放的仿真核心。

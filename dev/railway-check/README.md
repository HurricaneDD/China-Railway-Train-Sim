# 线路人工检查（dev/railway-check）

这是一个独立的线路拓扑人工检查页，用于分省核对当前运行数据中的正线断点、被过滤的端点连接和桥隧/层级过渡。它只读取 `data/` 下的正式分省 GeoJSON，不修改原始数据、不生成存档，也不参与驾驶。

## 打开方式

开发环境：

```bash
npm run dev
# http://localhost:8062/dev/railway-check/
# 外部访问示例：http://fangxx.fun:8062/dev/railway-check/
```

末尾的 `/` 不能省略。开发服务器会对 `/dev/railway-check`（无尾斜杠）返回 302 跳转到带斜杠地址；若使用旧进程或把该路径交给普通静态服务器的 SPA 回退，可能显示主应用首页。主应用的“设置 → 数据来源与许可”也提供入口。

生产构建会把页面输出到 `dist/dev/railway-check/index.html`。该页面不加载 Cesium；`vite.config.ts` 中的 `railway-check-html` 插件会移除 Cesium 插件注入到该嵌套页面的静态标签，避免相对路径 404。

## 底图、坐标系与车站

检查页提供两种高德底图：

- **高德普通**：高德标准街道瓦片（`style=8`）。
- **高德卫星**：高德卫星影像瓦片（`style=6`）。

高德瓦片是 GCJ-02，而线路、车站和断点的正式数据是 WGS84（EPSG:4326）。页面只在绘制显示副本时用 `src/utils/gcj02.ts` 把 WGS84 转成 GCJ-02，再按标准 Web Mercator（EPSG:3857）投影；地图网格和底图使用 GCJ-02 显示坐标，断点详情、导出 JSON、鼠标 WGS84 坐标和正式数据始终不被改写。底图归属“© 高德地图”绘制在画布右下角；瓦片加载失败时提示并回退到深色网格，线路与断点仍可检查。

断点标记预渲染为精灵，悬停高亮使用独立透明层，鼠标移动不会反复重绘整张地图；视图变换在绘制循环中缓存。省域 1,728 个断点的完整重绘在测试环境中约 4–5 ms。

地图使用高对比度配色：普通线路荧光黄绿、桥梁青蓝、隧道紫色，并加深色描边；断点使用高饱和红/橙/灰填充、白色内圈和黑色外圈；底图叠暗色遮罩。颜色只影响显示，不参与数据或拓扑判断。

车站来自 `data/stations.json`，只使用有有效经纬度的记录。当瓦片级别达到 **12 级**时，地图会绘制车站标记和站名，并做简单的标签防重叠；更低缩放级别不显示车站，避免省域视图被标签淹没。车站数据加载失败时，线路和断点检查仍可继续。“车站标注”复选框可随时关闭。

底图源和投影工具由主应用道岔配线图与检查页共用：`src/map/basemap.ts` 定义高德等瓦片源与坐标系元数据，`src/utils/mercator.ts` 定义投影和瓦片级别；本目录下的同名文件只保留为兼容导出。`stationLabels.ts` 负责车站显示坐标、站名截断和缩放阈值，`src/data/stations.ts` 通过注入的 `StationJsonFetcher` 读取嵌套页面所需的 `../../data/stations.json`。

## 数据与计算

- 省份列表来自 `data/provinces_index.json`，线路来自对应的 `data/geojson/<adcode>-<省份>.geojson`。
- 页面通过注入 `RailwayRepository` 的 `JsonFetcher` 读取 `../../data/`，适配开发服务器和 GitHub Pages 的嵌套路径。
- 拓扑规则与驾驶会话共用 `src/data/railway.ts`：原始 part 独立、2 m 端点节点、0.25 m 连接容差、0.25 m/35° 桥隧过渡限制。
- 共享原始端点（间隙 < 0.01 m）存在桥隧或 `layer` 标签差异时，只要转角不超过 35°，仍按几何连续性保留为可行驶候选，并标记为“不确定”。这是 2026-11-02 修复正线误断的核心规则。
- 桥隧识别仅依据原始属性：`bridge === 'T'` 为桥，`tunnel === 'T'` 为隧；`'F'`、缺失或其他值都不算。它不是结构检测，也不使用 DEM 或几何形态分类。

## 断点分类

- **存在被过滤连接**：到达节点没有有效出边，但存在被当前规则拒绝的非掉头候选。最值得优先检查。
- **邻近线路未接入**：没有候选，但 100 m 内存在其它线路区段。可能是省界、真实断头、站场股道或 OSM 缺口。
- **孤立端点**：100 m 内没有其它线路。可能是真实支线终点、站场尽端或更大的数据缺口。
- 只有“接近掉头”被拒绝的方向不会被视为断点，因为倒车回头由驾驶操作处理。
- 弱连通分量是按有效区段连接计算的并查集结果，忽略方向和区段内细分，不是实际可达性。

## 人工检查流程

1. 选择省份，加载当前原始数据。
2. 先看“重点”列表和红色断点；选中后查看来路、候选、间隙、角度、桥隧/层级标签。
3. 必要时勾选“加载相邻省份”，复核省界断点；已加载数据在本次会话内保留。
4. 开启“显示被过滤连接”查看被拒绝的几何连接；导出本省 JSON 作为修复线索。
5. 修复原始数据后重新加载，确认断点消失且未引入新的多出口误连。不要用本工具自动改数据。

## 验证

```bash
npm test
npm run build
```

`tests/railway-check.test.ts` 覆盖共享端点桥隧/层级过渡、0.55 m 间隙断点识别和孤立端点分类；`tests/mercator.test.ts` 覆盖 WGS84/Web Mercator 往返、瓦片层级和高德底图 URL；`tests/station-labels.test.ts` 覆盖车站 GCJ-02 显示配准、WGS84 无偏移、站名截断和 12 级显示阈值。页面已在开发服务器和无 Cesium 的生产构建中实际加载；完整浏览器驾驶验收仍以主应用为准。
